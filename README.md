# OTC 原生异动雷达

仅直接请求 https://otcdesks.cash；不呼叫 DEX Screener 或其他平台接口。OTC 后端自身上游来源不在本工具可核实范围。无钱包、交易或签名。

## 执行
Python 3.11+ 标准库。执行 `python monitor.py --port 8765`，开启 http://127.0.0.1:8765 。Windows 可使用 start.ps1；同时只启动一个采集实例。关机或休眠会停止采集，没有开机自启或云端托管。

测试：`python -m unittest discover -q`。前端逻辑测试需 Node.js：`node test-trend.cjs` 和 `node test-social.cjs`。运行服务本身不需要 Node.js 或 npm 安装。单轮采集：服务停止时执行 `python monitor.py --once`。

## 当前历史趋势规则
当前运行版本为 `otc-2.0+history-1.0`，详细定义见 [HISTORY_RULES.md](HISTORY_RULES.md)。新增持续放量、阶梯抬升、量价加速、突破回踩、上涨放量与回调缩量、多周期共振、老币复苏、持有人增长加速、流动性/市值九项历史指标。

正式趋势需持续放量，并至少满足阶梯抬升、突破回踩或多周期共振之一，同时满足流动性和涨幅限制。持有人增长只作为辅助。下方 OTC 2.0 分数保留为基础证据分，不是当前完整趋势规则，也不是上涨概率。

完整分钟市值 K 线和来源快照在本地保留 30 天，去重且不填补断档。详情显示逐项实测值和缺失原因，也提供来自 OTC 的 X 原始链接。品质统计包含信号后 5/15/30 分钟完整市值路径，缺测单列。仓库不包含本地数据库、日志、用户关注记录或测试截图，首次运行需要积累数据。

## 唯一直接资料来源
- /api/coins：列表、单币快照（价格、市值、流动性、持有人、24小时量、来源时间戳）。
- /api/chart：1_MINUTE、type=mcap，返回市值 OHLCV。成交量单位未核实，不标作美元。
- 网路层只接受以上两个路径，固定 HTTPS OTC 主机并拒绝重定向。
- 未提供买卖笔数、净流入、独立买家，这些不是新版规则必填资料。

## OTC 2.0 基础证据规则
- 快照来源时间不超过10分钟、本机接收不超过2分钟；未提供或过期不补造。
- 常规需15根连续完整分钟K线，最新收线不超过3分钟。首小时新币6根可弱预警。
- 相对量为近3根平均量除以前段最多30根中位数，门槛2倍；零基准保持未知。
- 五分钟市值涨幅 -1%～15%；近3根总涨幅正、至少2根收涨、回撤小于5%。
- 持有人至少20且比基准增加至少3。基准取来源时间相差4～15分钟且最接近5分钟的本地快照。
- 平台流动性至少5000美元且相对基准降幅不超过5%。这不是同池已验证深度。
- 四项各20分；突破前段高点加10分；后续新收线与更新来源摘要再次成立、五分钟市值涨幅至少2%才确认，再加10分。分数不是概率。
- 老币复苏另需发行超过48小时、基准振幅低于8%、相对量至少3倍。
- 旧事件保留规则版本；旧DEX行情不进新版判断，品质统计按版本分组。

## 预算与限制
新币每分钟最多3页，活跃榜每5分钟最多3页。追踪上限90，关注上限20。优先重用列表快照，每轮额外单币快照最多8次、K线最多8次、到期后续观测最多2次。K线错误退避最多15分钟。候选可能因预算或冷却漏判，不能把无讯号解读成市场无机会。

持有人基准需要累积不同来源时间戳，重复接收同一快照不增加样本。后续5/15/30分钟统计只接受来源时间落在到期至到期后120秒内的OTC价格；旧快照不冒充到期价格，缺测单列。

OTC 仍可能返回502、空快照或稀疏K线；直连不代表资料完整或即时。未经长期实盘观测与回测校准。

## 程式
monitor.py 为服务入口，otc_radar.py 为当前采集与判断。radar.py 保留旧版纯计算／事件生命周期以支援历史测试；旧第三方采集入口已禁用。SQLite保留原有历史。
